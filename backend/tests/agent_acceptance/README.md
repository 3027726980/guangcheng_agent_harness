由执行者按根 README 启动前后端并配置真实模型；保存模型配置可能发出连接探测请求。使用专门测试会话、带 `验收-` 前缀的待办，避免修改日常数据。场景 2、5 按顺序执行。对话和摘要模型都需配置有效连接，容量及来源如实记录，不将默认容量当成供应商保证。

## A1 普通问答

- 准备：新建空会话，无其他任务执行。
- 输入：`用一句话解释 Python 列表，不需要执行任何操作。`
- 步骤：发送，等待任务结束，打开该任务完整链路。
- 预期：回答与问题相关、非空，任务正常完成，没有工具写操作和新增待办。
- 证据：回答、任务 ID、Trace 中的模型调用与最终状态。

## A3 固定样例搜索与无匹配

- 准备：新建会话，当前 search 使用固定样例数据，不是联网检索。
- 输入 1：`请用 search 搜索 Python 入门资料，告诉我来源和主要内容，并说明它是否来自实时联网。`

## A5 双会话隔离与工具结果追问

- 准备：同一演示用户 A 打开两个窗口；窗口一选择 A2 会话，窗口二新建另一会话；确认不是同一会话 ID。
- 输入：窗口一 `记住这个会话代号是蓝鲸731。`；窗口二 `记住这个会话代号是红狐862。`；随后分别问 `这个会话的代号是什么？`
- 步骤：核对两窗口分别回答各自代号。在窗口一继续输入 `查询刚才创建的“验收-计算4608”，然后把它标记完成。`；最后窗口二输入 `请查询“验收-计算4608”的当前状态。`
- 预期：聊天代号不串会话；窗口一根据实际查询获得 ID、版本并完成正确待办；窗口二能查询到已完成状态，因为待办按用户共享，聊天历史按会话隔离。其他待办不变。
- 证据：两个会话 ID、代号追问、todo 查询与完成轨迹、目标待办最终状态。
