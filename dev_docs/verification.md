## 真实模型验收步骤

获授权启动服务后，按 README 配置连接并保存；这一步会真实发出模型请求。建议按下面顺序检查：

1. 直接对话后追问，确认同会话记忆；新建会话确认不自动继承聊天。
2. “计算 128 乘 36，把结果记入待办”，检查 Trace 中计算结果为 4608，待办确实落库；追问并完成待办。
3. 查询样例资料，确认页面和结果明确是 Mock，不把结果当实时搜索。
4. 用户 A 打开两个窗口分别建立会话，分别追问；两个窗口都能看到 A 的最新待办；用户 B 看不到 A 的会话与待办。
5. 输出时发送排队消息及引导；检查引导归当前任务、普通消息排队；分别测试最终文本阶段和工具阶段引导。
6. 模型输出／工具执行时停止，检查停止标记、部分内容和已提交操作；普通停止后下一条排队任务继续。
7. 关窗或断网，等待服务端检测断线；该客户端当前和排队任务取消，另一窗口继续；重连不自动重跑。
8. 对有小 Context 的测试模型持续输入，观察压缩覆盖范围和后续追问；不要为制造容量测试修改供应商真实容量元数据。
9. 在任务执行期间修改全局设置，当前任务保持快照，新任务使用新配置；重启后遗留任务有中断证据。
