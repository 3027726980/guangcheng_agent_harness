## 二、重点问题的修复细节

### B02：删除会话与运行版本不同步

- 删除属于当前用户的会话，采用逻辑删除，隐藏会话并拒绝继续访问，不删除执行证据或共享待办。
- 有运行或排队任务时拒绝删除，提示先停止／取消任务。
- 其他窗口接收删除事件并同步会话列表；避免同一窗口 HTTP 与 SSE 重复创建替代会话。
- 代码存在接口不代表已运行服务加载了接口；405 应检查当前服务的 OpenAPI 和启动版本。
- 验证包括 API 用户归属／忙碌拒绝，以及模拟浏览器确认删除、替代会话与共享待办保留。

### B03：执行顺序与连续过程展示

- 公开说明文字、用户消息和不同任务是执行组的分界，工具不再被统一搬到消息顶部。
- 同一任务内连续调用合并为“执行过程 · N 次工具调用”，默认折叠。
- 展开总入口后，每项调用仍独立折叠；再点击查看该项参数和结果。
- 同批并发调用按请求顺序展示，不代表实际完成先后；结果按调用 ID 配对。
- 组外汇总执行中与失败状态；结果到达时保留展开状态，长列表与长结果支持滚动。
- 验证包括连续跨批次合并、乱序结果配对、文字／任务边界、独立展开和 390px 窄屏布局。

### B07：断线提示收起与恢复

- 收起提示只影响展示，不删除原任务或事件，不将已经取消的任务伪装成成功。
- 当前窗口的 sessionStorage 按用户和会话保存收起记录，切换、重连、刷新后继续生效；不承诺跨浏览器永久保存。
- 重连只清除对应的顶部断线错误，无关业务错误仍保留。
- 验证包括收起、重新连接、会话切换和刷新，以及无关业务错误保留。

### B08：Enter 发送保留光标

- 发送请求期间 readonly 代替 disabled，避免浏览器失焦。
- 请求中重复 Enter 不重复提交，成功后可直接继续输入下一条。
- 发送失败时保留草稿与焦点；模型流式输出不移走输入焦点，也不主动抢回用户已经移到其他控件的焦点。
- 前端构建及浏览器模拟验证通过。

### B09：引导无反馈

- 实际服务只读检查确认当时缺少 `POST /api/runs/{id}/steer-queued`。
- 前端保留 HTTP 状态码：404／405 提示接口不可用及重启，409 等错误展示具体原因。
- 失败提示位于原队列消息旁，不再只依赖页面顶部；切换会话清理该局部提示。
- 引导成功时原消息转为当前任务的补充条件，不再独立执行；先显示“引导待生效”，在下一次模型调用前加入。
- 转换保持用户归属校验、幂等与现有任务预算；没有可引导任务时保留原队列消息。
- 已在当时获得授权后重启并确认接口加载；浏览器模拟覆盖 404／405／409、重试成功及局部状态清理。

### B10：压缩无法完成与长度限制移除

真实错误证据来自用户已经执行的压缩任务，而不是开发者新增的付费调用：模型为 deepseek-flash，约 7 秒后返回 `finish_reason=length`，`completion_tokens=1114` 且 `reasoning_tokens=1114`，未产生可用摘要正文。程序把自动计算的正文长度目标作为推理加正文的总输出上限，导致推理提前耗尽额度。

最终实现以 `7203b38` 为准：

1. 对话和摘要请求都不发送固定输出上限，使用供应商自身的默认限制。
2. 删除摘要正文长度目标、计算函数和相关事件字段，提示词不再要求特定 token 数或正文长度。
3. 输入分块、Context 空间预留和最终容量检查继续存在；这些是输入空间规划，不是摘要正文生成上限。
4. 检查输出结束标记及完整性，不截取残缺摘要后提交；失败保留原摘要、覆盖范围和完整历史。
5. 手动压缩后没有减少用量时不覆盖原摘要，并明确提示；失败反馈传递具体原因。

回归使用真实 OpenAI SDK 配合 MockTransport 模拟“带小上限则只有推理且截断，不带则返回完整摘要”，同时检查供应商仍截断时的错误提示和旧摘要保护。最后一次后端验证为 60 项通过；真实供应商修复后的压缩结果尚未复测。

此前自动重启加载修复的命令被自动审批策略拒绝，未执行；最新两次长度修复需重启后端生效。用户之后是否自行重启，本次文档整理未核对，因此不将其记为已经上线验收。

### B11：重试等待说明

- 当时只读事件记录显示模型收到 HTTP 429，30 秒来自既有默认重试间隔。
- 页面补充失败原因、等待秒数和当前次数／次数上限。
- 保留既有默认 3 次重试、30 秒间隔，并遵循供应商更长的等待要求；没有将重试等待解释为模型正在生成。
