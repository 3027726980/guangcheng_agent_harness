# 本次开发问题记录

## Git 未初始化与远端创建

目录原先只有原题、空白最终答题文件和规划，没有Git。先创建 main 基线，再切 dev/runtime。系统没有 gh，使用 Git Credential Manager 已有凭据调用 GitHub API 创建私有空仓库；凭据只在子进程内使用，不输出、不入库。

## 换行检查

初次新增文件已进入索引后，再增加 eol 属性不会自动重写已有索引内容。证据：`git ls-files --eol` 显示 pyproject 为 i/crlf。限定 backend/fronted 的 gitattributes 后执行对应源码的 renormalize，避免修改原题文件。

## Python 版本

uv 首次自动选择了本机其他 Python。新增 backend/.python-version 固定3.12并重新同步，实际验证在3.12环境进行。

## 并行测试的时间假设

初版用20ms等待观察并发，但每个工具启动事件需要持久化，不能假设第二个工具一定在20ms内进入。改为两个执行同时到达后释放的显式栅栏，验证并行上限及结果顺序。

## 窄屏侧栏

模板只在组件创建时读取 matchMedia，桌面缩为手机宽度不会自动折叠。增加媒体查询 change 监听，卸载时移除。390px设置页检查没有页面横向溢出。

## 取消与已提交写入

用户停止可能发生在业务事务提交后、结果回传前。工具执行器在取消时等待确认SQLite提交结果，再记录成功结果及 stop_requested；不以取消覆盖成功操作，也不自动重做写入。

## 兼容协议

不同服务可能要求 max_tokens 或 max_completion_tokens，推理强度支持也不同。将它们作为连接字段，默认不发送推理强度；错误明确返回，不静默增加重试。真实供应商仍需验收。

## 浏览器检查环境

使用 Playwright CLI 的浏览器内接口与静态资源拦截，不启动应用服务。CLI执行代码不提供普通 require，改由本地准备静态资源映射后注入。检查时必须重新载入最新构建，不能把相同Hash路由跳转当作整页刷新。
