# AI 辅助开发 Prompt 与问题解决记录

本文件记录本次使用 AI 的真实任务与决策，不伪造不存在的逐字模型输出或真实模型测试。

## 1. 需求讨论

用户提出：梳理笔试、结合 Pin 和开源 Agent、前后端分目录、逐项确认设计。随后明确统一 Agent、模拟搜索、共享待办、排队与引导、停止与断线规则、Context 256K 回退及全局设置。

AI 的作用：解释概念、阅读原题、对照当前源码、列出取舍、根据用户选择形成开发路线。用户明确撤销首版意图路由后，设计同步移除，而不是继续实现最初方案。

## 2. 实施指令

用户授权按路线实施、使用 Git、本地主分支与开发分支分开、每批提交、不推送，并在 GitHub 创建关联远端。

执行选择：main 保存原题和规划基线；dev/runtime 开发；创建私有空 GitHub 仓库并关联 origin，不上传代码。

后续用户明确要求“推送并列出一个测试的列表清单”，因此补充逐项验收清单，检查测试／历史敏感文件后推送开发和基线分支并核对远端；此授权覆盖先前本轮“不推送”的限制，后续发布仍需明确授权。

## 3. 开发任务提示要点

- 核心循环自行实现，SDK 只作为模型传输；不引入 Agent 框架主流程。
- Pydantic 统一工具 Schema、执行参数验证和 API 入口；类型校验不替代事务／归属检查。
- 手动停止与断线分别处理，写入证据与取消原因分开保存。
- Context 保留原始历史，摘要成功才推进覆盖范围，不能偷删摘要输入。
- 所有重试与摘要计入预算，测试使用可控时钟，不真的等待30秒。
- 前端基于 PinLayout，事件、任务、消息通过各自ID关联；不把不同窗口当前会话放进共享 localStorage。

## 4. 校验与修正

- Git 初始基线保留原题原格式；新增源码通过局部 gitattributes 统一LF。
- 为多工具并发使用显式同步栅栏验证，不依靠几毫秒 sleep 判断并发。
- 浏览器检查发现侧栏仅初次读取宽度，修复为监听媒体查询变化。
- 使用真实 OpenAI SDK 和假 HTTP 传输检查流式参数拼接、结束标记、重试分类与容量回退。
- 真实模型连接尚未由开发环境提供，不用假模型结果冒充真实供应商结果。

## 5. 项目运行时提示

实际系统指令保存在 `backend/app/runtime.py` 的 SYSTEM，摘要提示在 `context.py`。核心要求包括：模拟搜索显式说明、写入只认工具证据、依赖调用分步骤、修改待办先查ID和版本、历史资料不覆盖系统指令。

后续真实模型验收应记录模型、连接类型、配置、问题输入、实际 Trace、失败样例与修正，不把不完整聊天当成成功案例。
